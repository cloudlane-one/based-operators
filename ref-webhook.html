    The webhook module¤

    based_operators.webhook is the operator-side half of the admission webhooks recipe. An operator that registers on.validate or on.mutate handlers needs a server for kopf to serve them over — without one, kopf refuses to start. Importing this module arms that server, and the scaffold does the import for you with --webhook:

    kopf run operator.py -m based_operators.webhook --liveness=http://0.0.0.0:8080/healthz

    import based_operators.scaffold as scaffold

print(scaffold.WEBHOOK_MODULE)

    based_operators.webhook

    The module itself is part of the distribution rather than something the scaffold generates: templating Python is a no-go, and there is nothing project-specific in it — everything that depends on where the operator runs arrives through the environment.

    What it configures¤

    Importing the module registers one kopf.on.startup handler. When kopf starts, it turns on a kopf.WebhookServer listening on all interfaces, serving TLS from the mounted certificate, and it tells kopf to manage the webhook configuration objects named for the deployment:

    import inspect

import based_operators.webhook as webhook

print(inspect.getsource(webhook.configure_webhook))

    @kopf.on.startup() def configure_webhook(settings: kopf.OperatorSettings, **_: Any) -> None: """Serve admission webhooks over the mounted certificate.

    kopf calls this once, after the startup handlers ran and before any webhook
is needed, and reconnects the server whenever the certificate files change,
so a renewed certificate is picked up without a restart.

Args:
    settings: The operator settings kopf hands to every startup handler.
    **_: Any other argument a future kopf release may add.

Raises:
    RuntimeError: If the TLS material of the chart is not mounted, which means
        the webhook deployment of the chart is incomplete.
"""
cert_dir = _cert_dir()
settings.admission.server = kopf.WebhookServer(
    addr="0.0.0.0",
    port=_port(),
    host=_host(),
    certfile=cert_dir / _CERT_FILENAME,
    pkeyfile=cert_dir / _KEY_FILENAME,
    cadata=_ca_bundle(cert_dir),
)
settings.admission.managed = _managed()

    The environment it reads¤

    Variable Meaning Default
    WEBHOOK_CERT_DIR Directory holding tls.crt, tls.key and optionally ca.crt. /etc/webhook/certs
    WEBHOOK_PORT Port the server listens on; the chart points its Service at the same port, because the API server calls the endpoint kopf advertises. 8443
    WEBHOOK_HOST Hostname the API server calls — the in-cluster Service. localhost
    WEBHOOK_MANAGED Name of the [Validating/Mutating]WebhookConfiguration kopf creates and keeps in sync. based-operators-webhooks

    The defaults only apply outside a cluster, where the chart's environment is absent. The Helm chart sets all four on the operator container.

    The certificate directory must hold tls.key and either ca.crt or tls.crt; ca.crt is preferred when present, and otherwise the server certificate is advertised as its own CA, which is what a self-signed cert-manager issuer produces. Missing material fails loudly at startup rather than quietly at admission time.

    What the chart adds¤

    The chart generated by scaffold --webhook adds everything around the module:

    • a cert-manager Certificate (self-signed by default; point webhook.certManager.issuerRef at your own issuer otherwise),
    • a Service exposing the port kopf advertises,
    • the RBAC to create and patch the webhook configuration objects.

    kopf itself creates the ValidatingWebhookConfiguration and MutatingWebhookConfiguration and keeps them in sync with the handlers that are registered, reconfiguring them whenever the certificate renews.
